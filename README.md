# AI-Штурман технической поддержки (AI Navigator)

MVP API для анализа отдельной заявки через GigaChat с предварительным маскированием распространённых персональных данных и обязательной проверкой результата человеком.

## Что работает

- Защищённый `POST /api/v1/incidents/analyze` с Bearer-токеном приложения.
- Авторизация GigaChat: Basic-ключ → OAuth access token → Bearer-запрос к модели.
- Кэш токена только в памяти, обновление перед истечением срока и один повтор после 401.
- Проверка конфигурации при запуске, HTTPS с проверкой сертификатов, ограничение длины описания.
- Локальная демонстрация без ключей, автоматические тесты без платных API-вызовов.

Это анализ отдельной заявки. Кластеризация массовых инцидентов, RAG, векторная БД и интеграция со Sprint пока не реализованы. Regex-маскирование не гарантирует удаления всех ПДн: ФИО, адреса, пароли и произвольные секреты могут остаться. Используйте синтетические или предварительно проверенные данные; соответствие ФЗ-152 требует отдельной оценки.

## Быстрый запуск (Python 3.10+)

```bash
git clone https://github.com/KorrVyrN/ai-navigator-support.git
cd ai-navigator-support
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env`. Сгенерируйте токен доступа:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Запишите результат в `NAVIGATOR_API_TOKEN`, а ключ авторизации из кабинета GigaChat — в `GIGACHAT_API_KEY` (без префикса `Basic `). Выберите соответствующий аккаунту `GIGACHAT_SCOPE`: `GIGACHAT_API_PERS`, `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`. Укажите модель, доступную вашему аккаунту, в `GIGACHAT_MODEL`.

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000/docs, нажмите **Authorize** и введите `NAVIGATOR_API_TOKEN`. Вызовите `POST /api/v1/incidents/analyze` с телом:

```json
{"description": "На тестовом POS отсутствует связь с провайдером"}
```

Пример ответа (содержание зависит от модели):

```json
{"analysis": "Проверьте доступность сети и состояние канала...", "requires_human_review": true}
```

В HTTP-клиенте передавайте `Authorization: Bearer <NAVIGATOR_API_TOKEN>`. Ключ GigaChat клиентам не передаётся. Неверный токен возвращает 401, некорректное тело — 422, ошибка провайдера — 502 без его внутреннего ответа. `/`, `/health`, `/docs` и `/openapi.json` публичны; `/health` проверяет процесс, а не доступность GigaChat.

Если возникает ошибка доверия сертификату, установите доверенные корневые сертификаты по инструкции провайдера или задайте `CA_BUNDLE` с путём к PEM-файлу доверенных центров. Проверку TLS не отключайте.

## Docker

```bash
docker build -t ai-navigator .
docker run --rm --env-file .env -p 127.0.0.1:8000:8000 ai-navigator
```

`.env` и ключевые файлы исключены из контекста сборки. Для своего CA смонтируйте PEM-файл в контейнер и задайте `CA_BUNDLE` с путём внутри контейнера.

## Офлайн-демонстрация и проверки

```bash
python main.py
python -m pytest tests -v --cov=app --cov-report=term-missing
```

`main.py` читает только синтетические заявки и печатает маскированный текст. Он не вызывает GigaChat и не требует ключей. Тесты API используют фиктивные ключи и MockTransport.

## Аутентификация и хранение секретов

Это доступ одного доверенного клиента/оператора по общему сервисному токену. Пользовательских аккаунтов, ролей, JWT и refresh token приложения нет. Токен приложения сравнивается в постоянное время по SHA-256-хешам. Его нужно хранить в секретном хранилище сервера; `.env` подходит для локальной разработки и должен быть доступен только владельцу.

Для ротации `NAVIGATOR_API_TOKEN` сгенерируйте новый, обновите сервер и доверенных клиентов, перезапустите все экземпляры приложения. Старый токен после перезапуска больше не принимается. Ключ GigaChat ротируется через кабинет провайдера с обновлением окружения и перезапуском. Access token GigaChat хранится только в памяти процесса, очищается при закрытии и никогда не возвращается клиенту.

Не помещайте токен приложения во фронтенд публичного сайта. Для нескольких пользователей потребуются отдельные идентичности, роли и аудит. Перед внешним размещением настройте HTTPS, ограничение размера тела и rate limiting на reverse proxy. Приложение не хранит историю заявок и не записывает их тексты или заголовки авторизации в журналы.

Описание протокола: [официальная документация GigaChat](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api).
